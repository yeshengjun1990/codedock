# CodeDock

**给你的代码修一座码头。** CodeDock 把当前打开的编辑器窗口变成一台 MCP 服务器：网页端 AI（ChatGPT / Claude / Grok / Devin 等）通过一条地址"停靠"进来，就能读写当前工作区、执行验证命令、用 LSP 和诊断自查——改动全部走编辑器，**显示为 diff、Ctrl+Z 可撤销**，作用域就是**这个窗口打开的文件夹**（开哪个，桥哪个）。

- **看得见**：面板实时滚动 AI 的每一次工具调用，改了哪个文件、跑了什么命令、成功失败一目了然
- **收得住**：三级权限开关（Read / Edit / Execute 默认分级关闭），高危命令弹窗确认，令牌一键作废
- **接得快**：两种接入方式（见下），快到一句话

和独立服务版（`../server.mjs`）的区别：

| | 独立服务版 | 本扩展版 |
|---|---|---|
| 作用范围 | `config.json` 里写死的目录 | **当前窗口打开的文件夹**（开哪个就是哪个） |
| 改代码的方式 | 直接写盘 | 走编辑器 `WorkspaceEdit`，**显示为 diff，Ctrl+Z 可撤销** |
| 代码理解 | 纯文本搜索 | **LSP 语义导航**（定义/引用/符号/悬停） |
| 错误自查 | 无 | **`get_diagnostics` 读语言服务器诊断** |
| 启动方式 | 双击 `start.bat` | 编辑器里一条命令 |
| 需要开着编辑器 | 否 | 是 |

## 安装

扩展面板 → 右上角 `...` → **Install from VSIX**，或命令行：

```
code --install-extension codedock-1.5.0.vsix
```

### 从 MCPGO（1.4.x 及更早）升级

插件已更名为 CodeDock，为保持命名一致，配置命名空间从 `mcpgo.*` 改为 `codedock.*`。升级后需要动三处：

1. **settings.json 里的设置值**（隧道 token、端口等）：把 `mcpgo.xxx` 改名成 `codedock.xxx` 即可，值不变；不迁移也不影响运行，按需重填
2. **项目自定义工具**：把工作区里的 `.mcpgo/tools/` 目录改名为 `.codedock/tools/`
3. **连接地址**：令牌换了新的密钥库键位，首次启动会自动生成新令牌、地址随之变化——去连接器里更新一次；想沿用旧地址，把旧 token 填到 `codedock.routeToken` 设置里即可

## 使用

**默认不自动启动**：`codedock.autoStart` 默认关闭——装好扩展不会自行暴露公网。需要时用命令面板执行 **`CodeDock: 启动服务`**（或在面板设置里勾选「打开文件夹后自动启动」，之后只要窗口里打开了文件夹就会拉起服务；没打开文件夹不会启动——没有范围就没有授权）。手动启动会把连接地址复制到剪贴板；自动启动/重启不会覆盖你当前的剪贴板内容。

### 控制面板（主入口）

三个入口打开的是同一个面板：

- 点左侧活动栏的 **CodeDock** 图标（常驻小面板）
- 点右下角状态栏的 `CodeDock: 运行中`
- `Ctrl+Shift+P` → **`CodeDock: 打开控制面板`**（编辑器区大面板）

面板里可以直接：**启动 / 停止**、**复制连接地址**、**打开向导页**、**改全部参数**（端口、隧道方式、cloudflared/ngrok 路径、**ngrok authtoken**、**ngrok 固定域名**、追加说明）、**重新生成令牌**、**看日志**。

### 实时活动（看得见 AI 在干什么）

网页端 AI 每调用一次工具，面板里的「实时活动」就滚出一条记录：

```
⟳ run_command     npm test                        ← 正在执行
✓ apply_patch     src/app.js      +12 −3    24ms   ← 行数变化
✓ get_diagnostics (all)            clean    180ms   ← 错误/警告计数
✗ search_files    TODO                2ms          ← 悬停看错误详情
```

右侧那个徽章不是解析日志文本得来的，而是工具**直接返回的结构化数据**（`{ text, meta }`），所以改文案也不会把它弄坏。

**改动过的条目可以点**：点一下打开「AI 修改前 ↔ 现在」的并排 diff。编辑前的快照存在系统临时目录（不会污染你的 git status），保留最近 40 份。

- 标题右侧是统计：`12 次 · 失败 1 · 平均 45ms`
- **状态栏会实时显示当前正在跑的工具名**，干完自动变回 `CodeDock: 运行中`
- `set_todos` 发布的任务清单单独显示在「任务」区，同时同步到状态栏进度
- 因为改动走编辑器编辑管道，**编辑器里直接显示 diff，`Ctrl+Z` 即可撤销**

### 大进度条

AI 调用 `report_progress` 时，面板顶部会出现一条进度条：

```
正在执行测试                                   65%
████████████████░░░░░░░░░
跑完整测试套件，确认搜索模块重构没有回归
```

AI 不报百分比时，会自动退回用任务清单的完成比例（`3/5 项完成`），所以进度条总有东西可看。状态栏同步显示 `⟳ 65% 测试`。

想让面板常驻在**右侧**：`Ctrl+Shift+P` → **`CodeDock: 在右侧打开控制面板`**（或把活动栏图标拖到辅助侧边栏）。

## 两种接入方式

启动服务后（**`CodeDock: 启动服务`**，地址自动复制到剪贴板，形如 `https://xxxx.trycloudflare.com/mcp/<token>`），网页端 AI 有两种接法：

### 方式一：MCP 连接器（适合 ChatGPT / Claude / Grok 等大厂网页版）

大厂网页版的对话框不支持动态添加 MCP，需要在**连接器**里配一次，之后每个对话都能用：

1. 网页端 AI → **设置 → 连接器 / Connectors → 添加自定义连接器**
2. 名称随意（比如 `CodeDock`），**服务器地址**粘贴启动时复制的那条 `https://.../mcp/<token>`
3. **身份验证选「无身份验证（No authentication）」**——令牌已经在地址里，不要选 OAuth
4. 保存。**新开一个对话**，连接器即可用（部分平台需要手动开启这个连接器的开关）
5. 开工：直接派任务，AI 会自己发现工具、读文件、改代码、跑测试

- **一次配置，长期可用**：用 `cloudflare-named` 具名隧道或 ngrok 固定域名时地址永不变，配完再也不用管；cloudflared 快速隧道的地址在重启后会变，变了要回来改一次
- 用到需要权限的工具时（比如执行命令），AI 会收到明确的拒绝提示告诉你去面板开哪一级——开完立即生效，不用重连
- 验证连接是否活着：浏览器打开 `https://.../healthz`，显示 `ok` 即通

### 方式二：一句话接入（适合支持"粘贴即连 MCP"的 Agent 平台 / 镜像站 / 能执行命令的 agent）

有些平台的对话框里可以直接挂 MCP（比如通过一句话让 agent 自己完成握手），这时不需要去设置里配连接器：

1. 启动服务后，点面板里的 **复制接入语句**（或打开向导页，第 1 步就是它）
2. 把这句话**直接粘进 AI 的对话框发送**，内容形如：

   ```
   快速连接这个 MCP，明确使用规则、熟悉可用工具，做好处理接下来一系列工作的准备。

   MCP 地址：https://xxxx.trycloudflare.com/mcp/<token>
   （所有请求都以 POST + Content-Type: application/json 发送 JSON-RPC：第一个请求发 initialize 会返回完整使用规则，再用 tools/list 获取工具清单。）
   ```

3. AI 收到后会**自己完成握手**：先 `initialize`（这一步会拿到完整的使用规则——工作区范围、可用工具清单、权限边界、工作方式），再 `tools/list` 列出全部工具，然后等你派活或直接开始

- **为什么一句话就够**：`initialize` 返回的 `instructions` 里已经写清了一切——作用范围是哪些文件夹、路径越界会被拒绝、每级权限覆盖什么工具、改完要跑诊断自查。AI 不需要你解释任何规则
- 对**能执行 shell 的 agent**（如 Devin、本地 agent），向导页还提供完整 curl 手册：浏览器打开 `https://.../guide/<token>?format=text`，或面板点「打开向导页」，握手、列工具、调用三步的命令都可以直接复制

### 两种方式怎么选

| | 方式一：连接器 | 方式二：一句话 |
|---|---|---|
| 适合 | ChatGPT / Claude / Grok 网页版 | 支持 MCP 的 Agent 平台、能跑命令的 agent |
| 配置位置 | 平台设置里，配一次所有对话可用 | 对话框里，粘一次管一个对话 |
| 地址变了 | 要回连接器改一次 | 重新粘一句话 |

两种方式可以同时用，连接的是同一个工作区、同一套工具和权限。

**两种传输同时开着，用一个协议层**：

| 客户端 | 地址 | 传输方式 |
|---|---|---|
| 现代客户端（ChatGPT / Claude 连接器等） | `https://.../mcp/<token>` | Streamable HTTP |
| 只认 SSE 的客户端（如 Devin） | `https://.../sse?token=<token>` | SSE |

两者共用同一套工具、权限与工作区边界，行为完全一致。SSE 那条把令牌写在地址里，所以同样不用填鉴权头。向导页上两个地址都有复制按钮。

### 命令

| 命令 | 作用 |
|---|---|
| `CodeDock: 打开控制面板` | 状态栏点击 / 活动栏图标都指向它 |
| `CodeDock: 启动服务` | 起 HTTP 端点 + 云隧道，复制连接地址 |
| `CodeDock: 停止服务` | 停隧道、关端口、清理后台命令 |
| `CodeDock: 复制连接地址` | 重新复制 `https://.../mcp/<token>` |
| `CodeDock: 打开接入向导页` | 浏览器打开一页，含复制按钮和步骤 |

### 设置

| 设置项 | 默认 | 说明 |
|---|---|---|
| `codedock.autoStart` | `false` | 打开文件夹后自动启动（没有文件夹时不启动）；默认手动启动 |
| `codedock.port` | `8787` | 本地端口，只监听 `127.0.0.1` |
| `codedock.tunnelProvider` | `cloudflared` | `cloudflare-named`（固定域名）/ `cloudflared`（快速）/ `ngrok` / `none` |
| `codedock.cloudflareTunnelToken` | 空 | 具名隧道令牌（Zero Trust 里复制） |
| `codedock.cloudflareHostname` | 空 | 具名隧道固定域名，例如 `mcp.example.com` |
| `codedock.cloudflaredPath` | 空 | 留空时自动在桌面 `devin-mcp-bridge` 目录等处查找 |
| `codedock.ngrokPath` | 空 | 同上 |
| `codedock.ngrokConfigPath` | 空 | ngrok 配置文件（ngrok.yml） |
| `codedock.ngrokAuthtoken` | 空 | 填了就直接通过 `--authtoken` 传给 ngrok，不必改 ngrok.yml |
| `codedock.ngrokDomain` | 空 | ngrok 固定域名，例如 `your-name.ngrok-free.app`；留空用随机域名 |
| `codedock.openaiTunnelId` | 空 | OpenAI 隧道 Tunnel ID（企业或平台后台分配） |
| `codedock.openaiApiKey` | 空 | OpenAI 隧道 API Key / 连接凭据 |
| `codedock.openaiTunnelClientPath` | 空 | OpenAI 隧道客户端路径，留空使用 PATH 中的客户端 |
| `codedock.externalProviders` | `[]` | 外部 MCP 进程列表，启动后聚合其工具并以前缀 `<provider>__<tool>` 暴露 |
| `codedock.aggregateWorkspaceMcp` | `true` | 自动聚合工作区 `.vscode/mcp.json` 里声明的 stdio MCP 服务器（启动进程需要 Execute 权限开启） |
| `codedock.dotnetPath` | 空 | dotnet 可执行文件路径，留空用 PATH 里的 dotnet |
| `codedock.godotPath` | 空 | Godot 可执行文件路径，留空依次查 PATH 与工作区根目录 |
| `codedock.extraInstructions` | 空 | 追加给 AI 的额外说明 |
| `codedock.routeToken` | 空 | 留空则自动生成并保存在密钥库；改掉它可立刻作废旧地址 |

> 换 ngrok 的好处是**域名可以固定**，不用每次重启都去连接器里重填地址——在 ngrok 后台保留一个域名，填进 `ngrokDomain` 即可。

## 提供给 AI 的工具（29 个内置 + 聚合网关 + 项目自定义）

### Agent Skills 与工作区规范

| 工具 | 说明 |
|---|---|
| `list_skills` | 自动扫描并发现工作区中的 Agent Skills（`.agents/skills/*/SKILL.md` 等），返回各技能的 YAML 描述与路径 |
| `read_skill` | 结构化读取指定 Skill 的核心提示词及附件（如 `references/rules.md` 等） |

### 核心操作与长任务

| 工具 | 说明 |
|---|---|
| `read_files` | 读一个或多个文件 |
| `read_image` | **真的把图片发给 AI 看**（设计稿 / 图表 / 照片等图片文件），返回 MCP image 内容块 |
| `list_directory` | 列单层目录，目录在前 |
| `apply_patch` | 精确文本替换 / 整文件写入 / **删除文件** / **重命名移动文件**，全部**可撤销** |
| `find_files` | glob 查找文件 |
| `search_files` | 文本 / 正则搜索，带行号 |
| `run_command` | 执行命令（**Windows 上为 PowerShell**，其他平台为系统 shell）；`wait:false` 用于长任务，同时落盘至本地持久日志 |
| `get_command_output` | 增量读取后台命令输出；**支持 `offset` 游标**实现断点续读与流式分页 |
| `list_jobs` | 查看当前工作区所有活跃与近期的后台任务状态、退出码与执行耗时 |
| `send_command_input` | **向运行中的命令写 stdin** —— 支持交互式命令（确认、菜单、REPL） |
| `cancel_command` | 终止命令及其子进程 |
| `get_diagnostics` | 读语言服务器的错误与警告 |
| `lsp` | 定义 / 引用 / 实现 / 符号 / 悬停 |
| `report_progress` | 上报当前阶段 + 百分比，渲染成进度条 |
| `set_todos` | 任务清单，进度显示在状态栏 |
| `update_plan` | Codex 风格计划格式（`{plan:[{step,status}]}`），映射到同一张任务卡 |

### .NET 项目

| 工具 | 说明 |
|---|---|
| `dotnet_detect` | 报告已装的 SDK / 运行时，以及工作区里的项目文件 |
| `dotnet_build` | 编译，**返回结构化的错误列表**（`文件:行:列` + `CS` 码），不是一屏 MSBuild 噪音 |
| `dotnet_test` | 跑测试，返回通过/失败摘要 |
| `dotnet_run` | 运行（GUI / 服务用 `wait:false`） |
| `dotnet_publish` | 发布到目录，可指定 RID / self-contained |
| `dotnet_restore` | 还原依赖，用于修"包找不到"一类问题 |

**为什么值钱**：`dotnet_build` 把诊断解析成 `src/Program.cs:12:5 CS0103 The name 'foo' does not exist`，AI 可以直接跳到那一行改完再 build——这就是自动修复闭环。用 `run_command` 跑 `dotnet build` 只能拿到一整屏原始输出。

### Godot

| 工具 | 说明 |
|---|---|
| `godot_detect` | 找引擎、报版本、列导出预设、说明资源是否已导入 |
| `godot_import` | 导入资源（新拉下来的项目第一次跑之前必做） |
| `godot_run` | 运行项目；`headless:true` + `quit_after:N` 可做无窗口冒烟 |
| `godot_export` | 按预设导出，预设名是从 `export_presets.cfg` 里实际读出来的 |
| `godot_check` | headless 跑 N 帧，只报脚本/资源错误——改完代码问一句"还能加载吗"的最省事方式 |

需要在设置里填 `codedock.godotPath`（Godot 是绿色软件，路径随版本变化，所以不猜）。

**注意**：Godot 脚本报错时**退出码常常仍然是 0**，所以这几个工具判断成败靠扫输出里的 `ERROR:` / `SCRIPT ERROR:`，不靠退出码。

### 看画面（交给本地 MCP）

1.3.0 起**内置截屏工具已移除**（`screenshot` / `screenshot_window` / `run_and_capture` 不再存在，Capture 权限级同步删除）。如果需要让 AI 看见画面，接一个**带截图工具的本地 MCP** 即可，工具会以 `<名字>__<工具>` 的前缀出现在远程 AI 的工具清单里：

```jsonc
// 方式一：工作区 .vscode/mcp.json（编辑器原生格式，自动发现，JSONC 注释可用）
{
  "servers": {
    // 看运行结果：微软官方浏览器 MCP，能开页面、点击、填表、截图回来
    "browser": { "command": "npx", "args": ["-y", "@playwright/mcp@latest"] },
    // 版本管理：官方 git 参考实现（轻量，见下一节）
    "git": { "command": "uvx", "args": ["mcp-server-git"] }
  }
}
```

```json
// 方式二：用户设置 codedock.externalProviders（settings.json，不受工作区影响）
"codedock.externalProviders": [
  { "name": "shot", "command": "npx", "args": ["-y", "某个截图 MCP 包"] }
]
```

**安全边界**：`.vscode/mcp.json` 是工作区文件（远程 AI 有 Edit 权限就能改写），所以其中的服务器只有在 **Execute 权限开启**时才会启动进程，命令行还会过一遍危险命令确认；设置里的 `externalProviders` 是用户手配的，始终聚合。不想要这行为就把 `codedock.aggregateWorkspaceMcp` 关掉。

### 版本管理（Git 交给轻量 MCP）

内置不重复造 git 工具，接官方参考实现 `mcp-server-git`（Python/uv 生态，stdio，按需启动，轻量）：

```jsonc
// .vscode/mcp.json 或 codedock.externalProviders
{
  "servers": {
    "git": { "command": "uvx", "args": ["mcp-server-git"] }
  }
}
```

- 前置只有一步：安装 [uv](https://docs.astral.sh/uv/)（`winget install astral-sh.uv` 或 `pip install uv`）；uvx 首次运行会自动准备 Python 环境，无需手动装
- `--repository` 参数可省略——网关已把 cwd 设为工作区根，默认就在当前仓库上操作
- 提供 12 个工具：`git_status / git_diff_unstaged / git_diff_staged / git_diff / git_log / git_show / git_branch`（读）+ `git_add / git_commit / git_reset / git_checkout / git_create_branch`（写）
- **没有 push**：推送、rebase、远程操作仍走 `run_command`，所以 `git push --force` 依然会被危险命令确认拦住
- 它的 `git_checkout` 切分支、`git_reset` 撤暂存都是仓库级操作；**丢弃未提交改动**（`git checkout -- .`、`git restore .`）无论走哪条路都会命中危险命令确认

不想装 uv 的话，什么都不接也行：`run_command` 直接跑 git 本来就能用，MCP 只是让 diff/status/log 更结构化、不占 run_command 的输出上限。

## 项目自定义工具

在项目里放 `.codedock/tools/*.json`，把项目自己的例行操作注册成 AI 可调用的 MCP 工具：

```json
{
  "name": "run_tests",
  "title": "Run Tests",
  "description": "Run the project test suite",
  "command": "npm test -- {{file}}",
  "inputSchema": {
    "type": "object",
    "properties": { "file": { "type": "string", "description": "Optional single test file" } }
  }
}
```

- `{{name}}` 占位符从调用参数替换；**参数缺失直接报错**，不会跑半截命令
- 命令在工作区根目录执行
- `"capability"` 字段**只作展示，不参与授权**：清单是工作区文件，远程 AI 有 Edit 权限就能写一个"自声明 read"的 shell 模板来绕过 Execute 开关——所以 1.2.1 起**所有自定义工具一律按 Execute 门控**，真正只读的工具也一样（开 Execute 即可）
- 清单改完约 2 秒生效（带缓存，`tools/list` 不会每次读盘）
- 名字重复的会被忽略，并在日志里说明原因

新会话的 AI 因此不用每次重新"发现"项目的构建/测试方式。

## 可靠性

### 三种隧道怎么选

| 方式 | 域名 | 流量 | 门槛 |
|---|---|---|---|
| **`cloudflare-named`** 具名隧道 | **永久固定** | **无限制** | Cloudflare 账号 + 一个自己的域名 |
| `cloudflared` 快速隧道 | 每次重启变 | 无限制 | 免注册，下载即用 |
| `ngrok` | 固定（静态域名） | **有额度** | ngrok 账号 |

**具名隧道最省心**：域名永久固定、没有流量账单、完全免费。代价是需要一个域名（DNS 托管到 Cloudflare 也是免费的）。

配置步骤：

1. Cloudflare 后台 → **Zero Trust → Networks → Tunnels → Create a tunnel**
2. 复制隧道令牌 → 填到设置 `codedock.cloudflareTunnelToken`
3. 在隧道里加 **Public Hostname**：`mcp.你的域名.com` → `http://127.0.0.1:8787`
4. 把 `mcp.你的域名.com` 填到设置 `codedock.cloudflareHostname`
5. 面板里隧道方式选 **cloudflare-named**，保存

之后地址永久固定：`https://mcp.你的域名.com/mcp/<token>`，再也不用重配客户端。

### 改设置不会换地址

只有**隧道相关**的设置变化才会重建隧道；改其他参数（比如追加说明、图片开关）时，**隧道会被复用**——避免一次无关的配置调整就把 cloudflared 的随机域名换掉。

### 隧道会自己重连

隧道进程意外退出时自动重连，退避序列 `1s → 2s → 4s → 8s → 15s`，连续 5 次失败才放弃并提示手动重启。

- **ngrok 固定域名**：重连后地址不变，客户端完全无感
- **cloudflared 快速隧道**：重连后域名会变，面板立即刷新地址并弹提示，需要去连接器更新一次

### 健康自检

面板顶部会显示两端探测结果，每 90 秒自动刷新一次：

```
本地 ✓ 4ms · 公网 ✓ 132ms · 隧道进程 存活
```

- **本地**探测证明 HTTP 服务在答
- **公网**探测绕隧道出去再回来——这才是"你粘进客户端的那个地址现在能不能通"的唯一可信答案
- 隧道进程挂了会如实显示 `已退出`

掉线时你一眼就能分清是哪种故障，不用靠猜。

### 并发自动调节

Agent 一次并行发很多调用时，超出的会**排队**（默认 8 个并发，自适应上限最高 32），不会同时开二十个进程把机器打爆。

- 调用持续很快且有人在排队 → 上限自动抬高
- 平均耗时超过 3 秒、或出现进程级失败 → 上限自动降低
- 业务性错误（例如 patch 找不到匹配文本）**不计入压力**
- `get_command_output` / `cancel_command` / `send_command_input` **永不排队**，长命令随时能查能停

## 权限分级

**令牌只证明「谁在调用」，权限才决定「能做什么」。** 每个工具被标成三级，控制面板里随时开关：

| 等级 | 默认 | 覆盖的工具 | 含义 |
|---|---|---|---|
| **Read** | 开 | `read_files` `read_image` `list_directory` `find_files` `search_files` `lsp` `get_diagnostics` `get_command_output` `cancel_command` `report_progress` `set_todos` `update_plan` `dotnet_detect` `godot_detect` | 只观察，不改变任何东西 |
| **Edit** | 开 | `apply_patch` | 创建 / 修改 / 删除文件（编辑器里可 Ctrl+Z 撤销） |
| **Execute** | **关** | `run_command` `send_command_input` `dotnet_build/test/run/publish/restore` `godot_import/run/export/check`，以及**工作区 `.vscode/mcp.json` 聚合的 MCP 工具** | 执行 shell 命令、启动进程、驱动已启动的进程 |

三个关键设计：

- **Execute 默认关闭**：网页端 AI 接上就能读能改，但**不能跑命令、不能启动任何进程**，除非你主动打开
- **`cancel_command` / `get_command_output` 属于 Read**：观察和「停止」只会往安全方向走，而且撤销 Execute 之后必须还能停掉已经在跑的命令
- **自定义工具与工作区 mcp.json 不享受特权**：清单是 shell 模板、mcp.json 能声明任意进程，两者都归 Execute 管，危险命令还要过确认框

被拒绝的调用**不会静默失败**：AI 会收到一条明确说明（缺哪一级、去哪里打开），面板的实时活动里也会记一笔 `✗`，所以你能看见"它想执行命令、但被拦住了"。每次 `initialize` 也会把当前三级状态下发给 AI，它自己就知道边界在哪。

改权限**立即生效、无需重启**——策略是每次调用时读的。

### 危险命令确认（Execute 之上的第二道闸）

即使 Execute 开着，**看起来会毁数据的命令**也会先停下来问你：

```
远程 AI 请求执行一条高风险命令

命中：递归或强制删除（rm -rf）
目录：.
rm -rf ./build

[允许一次]  [拒绝]
```

命中的形态包括：`rm -rf`（含 `sudo rm -rf`、开关在操作数之后、GNU 长参数 `rm --recursive --force`）、`del/rd /s`、`Remove-Item -Recurse -Force`（含 PowerShell 别名与参数缩写 `ri -r -fo`、`del -r -fo`）、`cmd /c "rd /s …"` / `sudo sh -c '…'` 这类**引号包裹的嵌套命令**、`git push --force`（`--force-with-lease` 单独使用时放行）、`git reset --hard`、`git clean -f`、`format` / `mkfs` / `diskpart`、`shutdown` / `reboot`、`curl … | sh` 与 `iwr … | iex`、`powershell -enc …` / `-w hidden` 这类**隐藏或编码执行**、任意函数名的 fork 炸弹、`chmod -R 777`、`npm publish`、`dd of=/dev/…`。

**项目自定义工具（`.codedock/tools`）执行的命令走同一道确认框**，manifest 模板并不能绕过它。

**只有明确点「允许一次」才会执行**——按 Esc、关掉弹窗、或者三分钟不理它，都算拒绝，而且 AI 会收到一条提示叫它别再试。

这套检测是**启发式，不是沙箱**：它抓的是"一次失误就造成数据丢失"的命令形状，抓不全。所以它**故意做得窄**——`npm run format`、`git status`、`rm temp.txt` 这类正常命令不会被它打扰。一个弹得太勤、被无脑点掉的确认框，比没有确认框更糟。

## 安全

- 服务只监听 `127.0.0.1`，公网入口是临时隧道（cloudflared 快速隧道每次重启换域名）
- 鉴权用 **URL 即凭证**：token 在路径里。这条 URL 等同于该工作区的钥匙，**不要外发**
- **token 之外还有权限闸**：拿到地址也只做到你开的那一级；Execute 默认关闭
- 所有工具调用都要过 `lib/scope.js` 的路径校验，`../` 和越界绝对路径一律拒绝
- 换 token：改 `codedock.routeToken` 设置并重启 Bridge，旧地址立即失效
- 不想开公网：把 `codedock.tunnelProvider` 设为 `none`

### 1.2.1（安全修复）

- **移除 `/oauth/*` 端点**。原实现里 `/oauth/token` 不校验授权码就直接返回路由令牌——任何能到达隧道的人都可以凭隧道地址换取令牌，"URL 即凭证"退化成"URL 即全部"。文档化的客户端（ChatGPT/Claude/Grok 连接器、Devin、curl）都走 URL 令牌 / Bearer，OAuth 面直接删除而不是半修。
- **去掉全局 CORS `*` 与 `WWW-Authenticate` 广告头**。接入方都是服务端 agent，不需要浏览器跨域；保留 `*` 反而允许任意网页读取本机响应。
- **MCP 端点强制 `Content-Type: application/json`**。text/plain 的 JSON-RPC 会绕过浏览器预检，变成可以被盲发的简单请求。
- **工作区自定义工具（`.codedock/tools`）一律按 Execute 权限门控**。清单是工作区文件，远程 AI 有 Edit 权限就能写入——自声明 `"capability": "read"` 等于绕过 Execute 开关执行命令，不再信任。
- **路径校验增加 realpath 检查**。工作区内的符号链接 / junction 指向外部时（clone 仓库可能带出），读写无法再越出工作区。
- **`read_skill` 资源路径改用 `path.relative` 校验**。原 `startsWith` 前缀比较会放行 `skills-x` 这类同名前缀的兄弟目录。
- **高危命令识别增强**：新增「隐藏或编码执行的 PowerShell」（`-enc` / `-EncodedCommand` / `-w hidden`）；修复 `rm --recursive --force`（GNU 长参数）绕过 `rm -rf` 模式的问题。
- **license（CDK）模块接入启动流程**：未配置 `codedock.licensePublicKey` 时行为完全不变；配置后启动服务需要有效 `licenseKey`，并可在设置里搜索到该公钥项。
- **隧道可执行文件不再搜索 `~/Downloads`**（最容易被投放文件的目录），只认内置 `bin/`、显式配置和 `devin-mcp-bridge` 目录。
